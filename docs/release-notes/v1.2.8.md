## Loom 1.2.8: chains you can trust before, during and after

- **`loom chain --check`** checks every line before an hour of runs. It confirms the project exists, there are no uncommitted changes the merge would hit, `.loom/` is ignored, the orchestrator and workers are here, and the config has no typos. It also shows each worker's access. Nothing runs.
- **`--progress`** prints one line per task event while a chain or orchestra runs: planned, started, done with N files, failed and why, review rounds. With `--json` the events are JSON lines on stderr.
- **`loom defaults`** sets the agents every project gets and their access. `loom init` applies them: it adds and sets, and never removes or overrides what you chose.
- **Daemon swaps are said out loud.** "updated the daemon 1.2.7 → 1.2.8 — no turns were running" appears, and `loom version` shows it too. `loom config auto-restart off` keeps a long chain on the build it started with. A running chain or `orchestra --wait` now counts as busy, so no swap lands between two runs. If a restart happens anyway, they wait it out instead of failing.
- **Each phone gets its own Loom Cloud key.** Revoking a phone locks it out of the relay completely: it can no longer read the replies meant for your other phones. Phones paired earlier keep working until you run `loom cloud rotate` once.
- **The phone sends no usage ping before the welcome screen,** and the welcome says what is sent and where to turn it off.
