## Loom 1.2.0: a council of agents, and fixes from a real field test

Someone took Loom 1.1 through a full plan → review → build → proof run on a real project, with Claude Code, Codex, Antigravity and an OpenRouter model. They filed eighteen issues. 1.2 fixes all of them and adds the workflow they asked for: several agents checking each other's work, with only one of them writing.

### Council: plan, backtest, build, prove, forward-test, fix

```
loom council "add rate limiting to the API" --planner claude-code --reviewers codex,antigravity
```

One planner, up to four reviewers, one goal, one chat:
1. **Plan.** The planner plans and changes nothing.
2. **Backtest.** The reviewers test the plan in parallel, read-only.
3. **Decide.** The planner accepts or rejects each finding, and each answer is recorded as a decision.
4. **Build.** Only the planner writes code.
5. **Prove.** Proof re-runs the tests in a clean checkout.
6. **Forward-test.** The reviewers read the diff.
7. **Fix.** The planner fixes what it agrees with, and Proof runs again.

In the app, one card fills in stage by stage, with a Stop button. Your phone hears when it ends.

### Review: several agents, read-only, nobody takes the baton

`loom review codex antigravity` (the uncommitted changes by default, or `--file`, or `--text`):
- Each reviewer reads in its own plan mode where it has one, and never takes the baton, so there's no "hand off to codex?" prompt for a read.
- Their findings land in one list, worst first. Two reviewers on the same line show as one finding they **agree** on.
- **Accept** a finding and it becomes a project decision every agent is briefed with. **Reject** it and it's marked.
- A reviewer that changes files anyway is flagged.

### Scripting

- `loom send --wait [--json]` blocks until the turn ends and prints the reply and cost. Exit codes: 0 done, 1 failed, 2 the agent asked a question, 124 timed out.
- `loom doctor` now compares what the **daemon** sees with your shell: an agent missing from its PATH (naming the folder), a sign-in, or a key exported only in a terminal. It also checks that each provider answers, and suggests `pool:free` when a pinned free model keeps getting 429/503.
- `loom costs` and the Usage view show **"~$x est."** for agents that report tokens but no price (Codex, Grok): their tokens at the model's API price. The estimate is never added to the real total or to a budget.

### Fixed

- **Claude's Auto mode runs your project's commands.** It runs the test command, `cd <project> && …`, paths with spaces, and folders you list under `readPaths`. It refuses paths outside the project and commands that can't be undone, and every refusal says which rule fired and how to allow it. The permission badge says what each mode actually does.
- **A failed run is reported as failed.** An Antigravity turn that timed out or returned nothing was reported as success, and so was a failed subtask.
- **Proof leaves a plan alone.** It doesn't "check" a plan-only turn, and it doesn't count a command the agent was refused as one that ran.
- **Memory is credited only to a reply from a successful turn.**
- **Signed-out agents show as signed out** in `loom init`, the roster and Desktop, including agents learned from their "not logged in" errors.
- `loom status` says ◐ working. A model agent without write access shows as read-only.
- `loom providers` shows what the daemon sees. A key in your shell that the desktop app's daemon can't see is called out.
- `loom ask` checks provider keys before sending anything.
- `loom init` offers to add `.loom/` to `.gitignore`.
- The app is called **Loom Desktop** everywhere: Spotlight, the menu bar and the window.
- A spawned subtask's reply lands in the chat it was asked in.
