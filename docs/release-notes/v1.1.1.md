## Loom 1.1.1: a smooth first launch

Fixes found installing 1.1.0 on a Mac whose projects live on an external drive.

**Loom Desktop explains a slow start.** The first time Loom reads projects on
an external drive (or in Documents or Desktop), macOS asks whether Loom
Desktop may access those files, and Loom's background service waits for the
answer. 1.1.0 sat on a blank window meanwhile. 1.1.1 says *Starting Loom…*
straight away, and after a few seconds that macOS may be asking, and to
choose **Allow**.

**No second background service.** While the first one was waiting on that
prompt, 1.1.0 tried to start another onto the same port. 1.1.1 waits for the
first one instead.

**An installed app's error page.** If the service can't be reached, the page
now says to quit and reopen, where the permission lives in System Settings
(Privacy & Security → Files and Folders), and where the log is. It no longer
says "run npm run build". The pairing request also times out instead of
hanging.

**One build, one fingerprint.** Builds now remove compiled files whose source
is gone. Leftovers in an old checkout made the same release look like two
different builds to the desktop app and the CLI, and each would restart the
other's background service.

Everything new in 1.1 (Proof, Night Shift, Loop watch, Blast-Radius Shield,
Quota Relay, Review Triage, Scorecards, Replay, and more) is in the
[1.1.0 notes](https://github.com/nickthelegend/loom/releases/tag/v1.1.0).

### Install

- **macOS**: the `arm64` (Apple silicon) or `x64` dmg below. The app is
  ad-hoc signed, so the first time, right-click it, choose Open, then Open.
  Or use Homebrew: `brew upgrade --cask loom-desktop`.
- **Windows / Linux**: the installer for your platform below.
- **Android**: `loompad-1.1.1-android.apk` below installs over earlier versions.
- **CLI**: `npm install -g @loompad/cli`, then `loom up --restart`.
