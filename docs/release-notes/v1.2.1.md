## Loom 1.2.1: what two real field tests found

Loom 1.2 was put through two tests. The first was a full `loom council` on a real project: 23 tests became 52, and only the planner touched a file. The second ran six projects at once (a council, an orchestra, a route, a night shift, a crew and reviews), and the daemon never fell over. Together they found 25 things to fix.

### Proof tells "couldn't run" from "failed"
- **Which command:** Proof now re-runs the test command the agent itself ran and passed. Before, it guessed `python -m pytest`, got *command not found*, and reported "the tests fail" for a change that passed 52/52.
- **Just the test part:** it keeps only the test step of that command. `pytest | tail -3` always reports tail's success, so re-running it whole would pass failing tests.
- **Python projects:** a guessed pytest command uses the project's `.venv`, or `python3`.
- **If it can't start:** a test command that can't run at all is **unverified**, and Proof says how to set `proof.testCommand`.
- **On the council card:** Prove shows ✓ only when the tests really passed, ✗ when they didn't, **?** when unverified.

### The council keeps its word
- The planner's decisions are stored exactly as written. Underscores were being stripped, so `tests/test_reach.py` reached project memory as "testreach.py".
- The fix round gets **every** finding, low ones too. One dropped "low" was a test the planner had promised to write.
- A reviewer that answers with nothing counts as failed, not done.
- A reviewer that takes longer than `review.timeoutMin` (15 minutes by default) is stopped and left out, so one slow free model doesn't hold everyone up.
- Plans go to `.loom/plans/`, not a new folder in your repo.

### Sign-ins and cost
- Grok shows as **signed out** when its session has expired. Before, a leftover token made it look ready. `loom doctor` also reports a sign-in failure a real turn hit, even after a restart.
- `loom send` warns before re-reading a large session whose cache has expired, with an estimated cost. A one-line question once cost $4.75 that way. `--fresh` starts that chat's session over.

### Six projects at once
- **A council that waits for its own answer.** If a reviewer ran out of quota, its review was handed to the planner as a turn of its own, and the council read that turn as the planner's fix reply. Now a council waits for the reply to its own prompt, and a reviewer out of quota is simply left out.
- **Crews read every way of saying "changes requested"**, so a card goes back to its builder instead of the goal failing. New crews seat your writers as builders and your reviewers as reviewers, and `--builders` / `--reviewer` let you choose. `loom crew budget` works before the first goal.
- **Night shifts stay in order.** A loop-watch nudge goes in before the next task starts, and the report says what really stopped a task: the shield, the loop watch, Stop or a quota.
- **Fewer false alarms.**
  - Five different edits to one file aren't "going in circles".
  - A `curl -o /dev/null` later on the line isn't a delete outside the project.
  - A file Antigravity only mentions isn't an edit.
- **No silent hangs.** An OpenCode prompt that never starts fails after 3 minutes, not an hour, and `loom review --json` always prints JSON.
- **The baton comes home.** A route that ends on a reviewer hands the baton back to the agent that did the work.
- **You can see what's working.** `loom status` and the phone's project board count an orchestra, crew, council, shift or review as working.
- **The digest:**
  - In the app, "While you were away" shows the open project's digest and closes on Escape.
  - `loom digest` shows dates across midnight and collapses repeated lines.
- **Disk:**
  - Orchestra worktrees for a project on an external drive now live on that drive.
  - Finished runs' worktrees are removed after a week.
  - `loom doctor` points out folders left by projects you've removed, and `loom orchestra:clean` removes them.
