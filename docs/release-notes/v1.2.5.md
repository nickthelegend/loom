## Loom 1.2.5: steadier when agents do real work

### Updates don't kill running work
- **A newer CLI leaves a busy daemon alone.** It used to restart a daemon on an older build automatically, killing every turn in flight. Now it says to restart once the turns finish. `loom up --restart` refuses while turns run, unless you add `--force`.
- **`send --wait` says when a turn was interrupted.** It exits 75 with the command to carry on, instead of "fetch failed".

### Every agent starts, or says why
- **opencode starts with `OPENCODE_SERVER_PASSWORD` set.** Loom gives the server it starts a password of its own.
- **An opencode session that silently drops prompts no longer hangs.** Within 45 seconds Loom retries in a fresh session, or names the model that won't run.
- **A crashed opencode server ends the turn at once** instead of leaving the agent "busy" for up to an hour.
- **antigravity finishes its builds.** Every turn tells it the turn ends at its reply, so it runs tests in the foreground instead of waiting for a notification that never comes.

### Agent access
- **`loom agents:mode <agent> [bypass|auto|ask]`** shows what each mode means and switches it. For example, codex's default sandbox has no network and a read-only `.git`. `loom agents` shows each agent's access.

### Honest scripts
- `send` to an agent without the baton fails in a script instead of quietly exiting 0. `--handoff` takes the baton.
- A turn that reports no cost says `null`, not `$0`.
- `loom agents` outside a project lists what this machine can run. `loom status` marks the project you're in. `loom init` in a script keeps `.loom/` out of git.
